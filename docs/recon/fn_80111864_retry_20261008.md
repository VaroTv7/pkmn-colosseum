## Allocator Investigation

A subsequent investigation used two independent read-only reviews and new
captures from the actual configured GC/1.3 compiler. Its SHA-256 remains
`4e502c38465500d4fda8d966b268151a6c74c730508e3d9b7efd23d1a6083715`.
The compiler was observed, not patched or given artificial register bindings.

The earlier explanation that WZX loses its named-variable identity is
incomplete. The first backend copy-propagation pass does discard that copy,
but the resulting call-return register can be allocated early or late.
The determining difference is the interference graph's simplification history:

- GC/1.3 simplifies nodes with current degree below 29 in ascending virtual
  register order, then assigns colors in reverse removal order.
- If simplification stalls, it computes costs and optimistically removes the
  node with the lowest cost/current-degree ratio. This need not cause a spill.
- In the live seed's first residual core, WZX has ratio 19/31, slightly below
  the start pointer's 19/30. WZX is removed first and ultimately receives r15.
- Coalesced-away address nodes still contribute interference. A destination
  address copy can therefore prevent simplification despite emitting no move.

The generic read-only replay reproduces all assignment-order entries and
noncoalesced physical colors in **17/17 fn_80111864 captures**. It consumes
captured edges and costs; it does not independently recompute liveness,
coalescing, or the compiler's cost calculation.

A reduced 604-byte probe preserves the late WZX/r15 behavior while removing
bulk output copies and the direction gate. It is a diagnostic, not a candidate
implementation. In a related reduced probe, removing the extra start identity
changes WZX from r15 to r24 and avoids the cost pass, exactly as replay predicted.
An initially smaller probe did not retain the stalled core and was insufficient.
